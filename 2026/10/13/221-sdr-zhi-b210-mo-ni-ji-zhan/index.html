B210 搭建 LTE 基站

用 USRP B210 和 srsRAN 4G 搭一个抓 IMSI 的 LTE 基站。一开始在 VMware 虚拟机里怎么都跑不通，折腾了几十个会话；换到物理机后 11 秒就抓到了 IMSI。

卡点是虚拟机的 USB 虚拟化层，不是配置问题。

本文涉及两种环境，读的时候对照着看。第 7 节之前的内容都发生在 VMware 虚拟机里，之后是迁到物理机的记录。两边配置完全一样，只有运行环境不同，结果一边永远抓不到、一边 11 秒抓到。

背景

目标是 IMSI 空口采集。思路是自建一个 LTE 小区，让手机发起 Attach，在空口上截获 IMSI。

UE 发起 Attach Request 时，IMSI 明文放在 NAS 消息里，鉴权失败不影响截获。不需要让手机真正连上，只要它肯发起接入尝试。

前提是基站能持续发射。

一开始实验环境是 VMware 里的 Ubuntu 虚拟机，宿主 Windows。麻烦都出在这。

需求

让 B210 发一个合法的 LTE 小区信号，广播指定 PLMN。等手机发 PRACH。在空口上抓 IMSI。

在虚拟机里，前两步没能走通。

配置前还要弄清四条规则，答案都对着源码查过：

  • PRACH 在频域上占哪几个 PRB，跟带宽什么关系
  • EARFCN 怎么换算成频率，频段从哪里来
  • 一个小区能广播几个 PLMN
  • 手机在什么情况下会去搜一个陌生的频点

频段与 EARFCN

srsRAN 不需要你告诉它用哪个频段，只给 dl_earfcn，频段由内部表推出来。表在 lib/src/phy/common/phy_common.c 的 lte_bands[]：

频率这样算：

频段 fd_low dl_offset 化简
Band 1 2110 0 2110 + 0.1*N
Band 3 1805 1200 1805 + 0.1*(N-1200)

验算一下。Band 3 的 EARFCN 1300：1805 + 0.1*100 = 1815.0 MHz，日志打出来就是 DL=1815.0 Mhz。Band 1 的 300：2110 + 30 = 2140.0 MHz，日志也是 DL=2140.0 Mhz。

这里有个常见误解：以为 Band 3 的 1300 对应 1210 MHz。那是漏掉了 dl_earfcn_offset=1200，把 Band 1 的公式套上去了。

虚拟机环境的问题

现象

B210 的绿灯在闪，红灯几乎不亮。基站日志反复刷：

手机始终不接入。飞行模式切换、手动选网、贴天线都试过。

基站日志里搜 PRACH|Random Access|Msg1|Msg3|RRC Connection|Attach|rnti 零命中，手机没发过接入请求。

红灯

查了 Ettus 的 B2x0 手册，TRX 指示灯的语义是明确的：灭表示无活动，绿表示接收，红表示发送，橙表示收发切换。

红灯几乎不亮，说明发射没有连续工作。红灯在跑 benchmark 时是持续亮的，所以硬件没问题。

直通的真相

客户机里的 USB 控制器是：

两种直通完全不同：

类型 直通的是什么 数据怎么走
USB 设备直通 单个 USB 设备 经宿主机用户态服务转发

这里用的是第一种。VMware Workstation 不支持第二种。

每次 USB 传输要过四道边界。lsusb -t 里 B210 各接口的 Driver= 为空，由用户态 libusb 通过 usbfs 操作，每次传输都要走 ioctl 到虚拟机监控器再到宿主机。

虚拟机环境的结论

软件配置是对的。srsRAN 正常，B210 正常，S1 接口也通（Received S1 Setup Request / Sending S1 Setup Response 都正常）。断点只有一个：RF 发射不连续。

调参解决不了。九项优化全试过，包括官方脚本的三项、实时调度、CPU 绑定、关日志关抓包、降到 6 PRB。

要往下走只有两条路：物理机装 Ubuntu（或 Windows 双系统），或者换 Linux 宿主用 KVM/QEMU + VFIO 把整个 USB 控制器做 PCIe 直通，需要主板支持 VT-d 或 AMD-Vi。

为什么停在鉴权

srsEPC 的 user_db.csv 里没有这张卡的 K 和 OPc，发不出 Authentication Request，手机等待超时后 Detach。

这不影响采集。UE 在 Attach Request 阶段就要上报 IMSI，此时 NAS 消息还没加密，鉴权发生在之后。要跑通完整接入（分配 IP、ping），需要拿到卡的密钥，普通商用卡拿不到。

硬件

任意 x86_64，4 核以上，8 GB 内存以上。Ubuntu 22.04 LTS，物理机安装或者 Windows 双系统。USB 口必须是 3.0，蓝色那个，直连主板不要过 hub。笔记本记得插电源。

双系统的话，先装 Windows 再装 Ubuntu，让 GRUB 引导，给 Ubuntu 留 60 GB 以上。

可以不改。我的物理机在 powersave 下 benchmark 依然全零，就没动它。如果想保险起见，改一下也就一条命令。

选点原则

手机不接入的原因

手机不做全频段盲扫。它只测量当前服务小区在 SIB 里广播的邻区频点，这是省电设计。

手机测量列表里只出现过 1650、1850、2452、1506、50、150、3739 这些频点，全部来自真实网络配置。基站配在 EARFCN 300，这个频点从未出现在手机的测量结果里。

驻留频段和扫描频段是两回事。手机实测驻留轨迹是 B5(2452) → B3(1850) → B3(1650)，全程没进过 Band 1，而基站配在 Band 1。

同 PLMN 也不保证接入。手机在真实网络上待机时没有理由切到陌生小区，重选要满足门限，且该小区需在邻区列表内。

这就是为什么必须切飞行模式。试过不切飞行模式、只做手动选网，手机毫无反应。切一次飞行模式，手机重新搜网，才会去扫它记忆里的频点，这时才能碰到自建小区。

实测 EARFCN 1650 有效：手机曾经测到过它，配上去 11 秒就完成了接入。

不切飞行模式怎么让手机接入

这一节和运行环境无关。前面说过”必须切飞行模式”，这里把原因和替代方案讲透。

手机为什么不来

关键在 SIB1 里广播的 TAC（Tracking Area Code）。手机的逻辑是这样：

手机在真实网络上是注册状态，记着当前的位置区。看到自建小区时，它要判断”值不值得搬过去”。

这里有三道门，每一道都可能拦住它：

门 条件 为什么拦住了
频点 手机只测 SIB 邻区列表里的频点 EARFCN 不在列表里，手机根本不知道有这个小区
S 准则 服务小区信号要低于门限 手机在真实网络上信号很好，不满足”服务小区变差”
R 准则 目标小区排序要优于当前 自建基站功率低，排不过真基站

三道门全过，手机才会重选过来。而只要有一道不过，它就一直待在真网络上。

飞行模式做了什么

切飞行模式实际上执行了三件事：

关键在第二步。清空列表后手机回到未注册状态，这时它看到任何能用的 PLMN 都会去接入，重选的三道门都不再起作用。飞行模式之所以好使，就是因为它把注册列表清空了，而不是单纯让手机更容易切过来。

四个替代方向

方向 原理 可行性
屏蔽真实信号 让服务小区消失，手机被迫重新搜网 最有效，等同飞行模式但更自然
调 SIB 重选参数 让自建小区在 R 准则里排序更高 可试，纯软件
撞频点 把基站配在手机邻区列表里的频点上 已实现（EARFCN 1650）
等周期 TAU 手机的 T3412 定时器到期后主动上报 不可靠，可能几十分钟
提高功率 信号强度超过真基站 不现实，真基站 20–40 W

屏蔽是最实用的。把手机放进屏蔽箱或法拉第袋待一会儿再拿出来，效果和切飞行模式一样，而且更接近真实攻击场景，现实中的 IMSI catcher 也是靠干扰真实信号逼手机掉网。

调 SIB 重选参数

这是唯一纯软件、可控制的方向。sib.conf 里相关的字段：

字段 作用 调法
q_rx_lev_min 小区最低接收电平 调低，让手机觉得”这个小区能用”
q_hyst 重选迟滞 调低，减少切换阻力
cell_resel_priority 小区重选优先级 调高，让自建小区更有吸引力
thresh_serving_low 服务小区低门限 配合使用

思路是让自建小区在手机眼里”更值得去”。

但这有个前提问题： 这些参数生效的前提是手机已经知道有这个小区。如果 EARFCN 不在邻区列表里，手机连测量都不会做，参数调了也没用。

所以顺序是：先解决”能被测到”，再解决”值得去”。

EARFCN 1650 已经解决了第一层（实测有效）。第二层就靠这些参数。

先纠正一个坑。sib.conf.example 里有句注释说 q_rx_lev_min 要乘 2，那句注释是错的。源码 si.cc:3562 是 pack_integer(bref, cell_sel_info.q_rx_lev_min, (int8_t)-70, (int8_t)-22)，写 -70 就是 -70 dBm，没有缩放。

关键机制

方向性问题，容易搞反：

参数 调整方向 效果
q_hyst 调小 服务小区与邻区的排序差变小，邻区更容易胜出

s_intra_search 调高 门限越高越容易满足 Srxlev ≤ S_intra_search，更愿意测量同频邻区
t_resel_eutra 调小 满足条件后更快执行重选
cell_resel_prio 调大 绝对优先级更高

s_intra_search 那条最容易理解反。手机只有在服务小区信号低于这个门限时才会去测量邻区，所以门限调高 = 更容易触发测量。

结论：瓶颈在频点，不在参数

手机驻留到某个小区后进入待机态，此时它只测量当前服务小区 SIB 里列出的邻区频点，不再做全频段搜索。EARFCN 1650 不在邻表内，手机根本不去测，参数再激进也无从生效。

先澄清一个容易理解反的地方：手机不是从不全扫。开机或失去服务时它会做初始全频段搜索，只有驻留之后才受邻表约束。这也正是绕开限制的方向，想办法让它失去服务。

还有一点：「周围有同运营商的基站」不等于「进了邻表」。邻表是运营商在 SIB 里下发的短清单，只含它认为你可能需要切换的那几个频点。周围的基站可能几十个，列表外的对手机不存在。

信号检测仪的原理

这一节和前面是两个不同的东西，先分清。

类型 干什么 典型设备
频谱仪 / 扫频接收机 只看信号”在不在、多强”，不解协议 RTL-SDR、HackRF、Keysight N9020
基站模拟器 / 路测仪 能解协议、能当基站、能登记手机 罗德与施瓦茨 CMW500、安立 MD8475
IMSI 检测仪 主动广播假小区，骗手机来登记 就是本文在做的东西

USRP B210 + srsRAN 本质上就是一台 IMSI 检测仪。商用产品叫 IMSI Catcher，3GPP 里的正式术语是 False Base Station（伪基站）。

工作原理

核心思路：手机看到”更好的小区”会主动搬过去。检测仪造一个假小区，等手机搬过来时自报家门。

第 3 步是关键。真基站不会随便问 IMSI（只在寻呼不到 TMSI 等特定场景），但假基站没得选，只能直接问。

四代演进

代际 原理 是否暴露
2G（GSM） 强制关掉加密，直接要 IMSI 手机可能显示”无加密”警告
3G/4G 要 IMSI 后不鉴权，放走 较隐蔽
4G 高级 要完 IMSI 再”中转”到真基站 很隐蔽
5G SUCI 加密了 IMSI 基本失效

5G 的 SUCI 机制就是专门防这个的。手机上报的是加密的 SUPI，检测仪拿不到明文 IMSI。

这一点在做 5G 之前必须想清楚。

估计实际输出 约 +10 到 +15 dBm
覆盖范围 几米到十几米，一个房间

tx_gain = 89 是 UHD 的增益寄存器值，不是功率单位。B210 增益范围 0–89.75 dB，89 已接近满档。真实功率需要仪器实测，本文未校准。

不同功率的直观概念：

功率 场景
+15 dBm（32 mW） 几米到十几米
+20 dBm（100 mW） 几十米
+30 dBm（1 W） 几百米
+43 dBm（20 W） 真基站级别

商用检测仪通常 +30 到 +43 dBm（车载/固定式），比 B210 高 20–30 dB，也就是 100–1000 倍。

但功率大不管用，三个理由：

  1. 干扰合法网络，同频发射会干扰真实基站，这是违法的，官方文档也反复警告
  2. 抢不过真基站，真基站单天线通常 20–40 W（+43 到 +46 dBm），用 +15 dBm 覆盖它等于拿蜡烛照太阳
  3. 手机不看绝对强度，重选要看多个门限，不只是”谁信号强”

所以让手机过来的正确做法是”伪装”而不是”压制”：

手法 原理
模仿真实 PLMN 广播 46011，手机以为是自家网
调高重选优先级 SIB 里 cell_resel_priority 设高
降低接入门限 q_rx_lev_min 设低
降低真实信号 屏蔽箱、法拉第袋
逼手机重新搜网 飞行模式、重启、进无信号区

想测实际功率

设备 价格 说明
功率计（如 ImmersionRC） ¥300–800 直接读数
频谱仪 + 衰减器 贵 准确
简单办法：看距离 免费 拿台手机逐步远离，看多远还能扫到

注意：一定要接天线再发射。不接天线（开路）会损坏功放。

合规提醒

行为 法律状态
屏蔽箱 / 线缆内实验 基本安全
低功率空口发射，短时间 灰色地带
高功率广播覆盖公共区域 违法
干扰他人通信 违法，可入刑

《无线电管理条例》规定，擅自使用无线电频率可处 5 万到 50 万元罚款，情节严重的追究刑责。官方 srsRAN 文档同样警告：

Operating a private 5G SA network on cellular frequency bands may be tightly regulated in your jurisdiction.

本文的做法（低功率、自己的手机、短时间）属于研究性质，但仍建议尽量用屏蔽箱、避免在公共场所长时间发射。

一句话总结

检测仪的原理是”假扮基站骗手机自报家门”，不靠功率靠伪装。B210 大概 +15 dBm，覆盖一个房间；商用设备 +43 dBm，差 1000 倍，但核心手法完全相同，Identity Request 那一问才是关键。

5G 上这招基本失效，因为 SUCI 把 IMSI 加密了。

srsran

手机attach测试

触发方式

必须切飞行模式，否则手机不会来。原因见上面「手机不接入的原因」，手机在真实网络信号好时没有理由重选到弱小的陌生小区。

切飞行模式实际做了三件事：关闭射频、清空已注册的跟踪区列表、重新开机扫频。重新开机后手机处于”未注册”状态，看到能用的 PLMN 就会尝试接入。

理论上还有别的触发方式（调 SIB 重选参数、等周期 TAU、进无信号区），但都不如飞行模式可靠。

采集结果

成功。IMSI 15 位，460 11 开头（中国电信）。从基站启动到取得耗时约 11 秒。

详细的接入链日志见上面「物理机环境：成功」一节。

问题

  1. USB 3.0 带宽限制

  2. 我的电信卡接的是联通的网络

电信和联通有 5G 共建共享协议。电信用户接入联通的 n78（3.4 GHz）基站是标准行为，不是异常。

  1. 可在 *#*#4636#*#* 工程模式中，设置网络模式为 lte only

  2. 卡在虚拟机上折腾了很久

根本原因是 VMware 用的是 USB 设备级直通，不是 PCIe 控制器直通。客户机里的 USB 控制器是 VMware 模拟的（15ad:0779），每次传输都要经宿主机用户态服务转发。

宿主机 Windows 不是实时系统，线程调度粒度约 15.6 ms，而 LTE 要求每 1 ms 交付一个子帧。这个差距在客户机里补不上。

换物理机后，同样的配置一次就通。
