Orange Pi Zero 3W 编译 Android 13

记录这块 Zero 3W 编译 Android 13 的过程和期间遇到的 51 个问题。板子是全志 A733，6GB 内存，内核 5.15。这次改动包括接 RTC 和功放、默认中文、删除预装应用。

环境

项目 配置
系统 Ubuntu 22.04.5 虚拟机
CPU 和内存 8 核，19GB
磁盘 整套编译完约 200GB
源码 官方 SDK，9 个分卷，共约 37GB
TF 卡 64GB，/data 约 54GB。之前的 8GB 卡只有 2.9GB
烧录 Windows，PhoenixCard 4.2.8
调试 USB 转串口，adb，scrcpy 5.0.1

SDK 放在 ~/zero3w/src/a733_android13。排查启动问题时查到全志有篇文档叫「SDK所在目录路径过长引发固件异常无法启动」。

此环境下编译一共持续了6小时左右。

SDK 结构

SDK 在 AOSP 外面套了一层全志的构建系统：

层 位置 内容
AOSP 根目录大部分 框架、系统应用、工具链
longan longan/ 内核、设备树、boot0、U-Boot、打包
产品配置 device/softwinner/ 属性、overlay、预装应用

AOSP 的 m 不编内核，只把 longan/out 里的内核和设备树复制过去，所以编译顺序是 longan、m、pack。改完 board.dts 只跑 m，设备树不会更新。

顶层的 kernel/ 只有配置和预编译文件。内核源码在 longan/kernel/linux-5.15/，全志驱动在 longan/bsp/。全项目有 12 个 board.dts，这块板子用的是：

编译流程

1. 内核和设备树

2. 启动 buildserver

pack 要求这里的结果至少是 2。

3. 编译 Android

m 和 pack 是 envsetup.sh 里的 shell 函数，放在同一个 shell 里执行。根目录没有 Makefile。

4. 打包

产物是 longan/out/a733/demo_aiot/a733_android13_demo_aiot_uart0.img，约 1.8GB。每次打包文件名相同，我出包后马上改名归档。

SDK 自带的 b.sh 会一次跑完内核、m、pack。我是分步跑的，打包前多看一眼 buildserver。

5. 烧录

打包后先检查 boot0，再用 PhoenixCard 整卡烧写。镜像是全志的 IMAGEWTY 容器格式。

验证记录

检查项 当时的做法 后来的做法
改动是否进 system.img 直接 grep，EROFS 压缩后搜不到 out/host/linux-x86/bin/fsck.erofs --extract=/tmp/x system.img
内核配置 看 /proc/config.gz，内容是旧的 查 /proc/kallsyms 和 /sys/bus/*/drivers/
函数是否编入 在 .o 里 nm，LTO 下只有 bitcode 反汇编 vmlinux
App 方法是否改动 dex 里搜方法名，已被 R8 内联 搜方法里的字符串常量
引脚电平和上拉 读 Pn_DAT 输出寄存器 看 pinconf-pins 和 pinmux-pins
两个镜像的功能差异 逐字节比内核，调试段路径造成大量差异 比字符串集合和符号数量
PWM 通道 按节点名猜 pwm1@2528017 里是 0x10 加通道 7

有一次 dexdump 搜索写错了格式，方法引用其实是 类名;.方法名。目标和对照项都是 0 条，我才发现是搜索写错了，之后查“不存在”都带一个对照项。

还有一次把 0xF1 算成 305，读到全零，误判 boot0 损坏。0xF1 是 241。

/data/property/persistent_properties 里已有的键，即使值为空，也会挡住 build.prop 的默认值。这个文件是 protobuf，我一开始按长度前缀解析失败，后来按记录的字节区间删除。

手工把 vendor_boot 写进镜像后，PhoenixCard 报校验失败。容器里每个分区有一条 V 开头的校验记录，比如 Vboot.fex，内容是分区按 32 位小端累加的和。boot0 不在容器条目里，没有这条记录。

外设

板子没有板载 RTC，原理图上只有一颗 32.768kHz 晶振。board.dts 里的 rtc@51 继承自 4 Pro，实际没有这颗芯片，开机报错无影响。我先后接了 DS1302 和 DS3231。

DS3231

目前在用，走硬件 I²C：

模块 40pin SoC
VCC 1 3.3V
GND 6
SDA 3 PB3
SCL 5 PB2

模块的 I²C 上拉接在 VCC 上，所以 VCC 接的是 3.3V。

开机后 /sys/class/rtc/rtc0/name 是 rtc-ds1307 0-0068，date +%s 和 since_epoch 一致。新芯片第一次开机打印 SET TIME!。驱动绑定后，i2cget 报 Device or resource busy。

有一次 i2cdetect 全是 --，软件配置都对，最后发现 SDA 和 SCL 两根线忘了插。插好后重启，驱动才绑定上。

DS1302

DS1302 报 junk in control register。它要求 LSB 先发，5.15 的 spi-gpio 声明了 SPI_LSB_FIRST，实现里只有 MSB，驱动读控制寄存器时芯片收到的是读 RAM。

我在 spi-gpio.c 里加了位反转，并给 mode_bits 补上 SPI_LSB_FIRST：

defconfig 打开了 CONFIG_RTC_DRV_DS1302、CONFIG_SPI_GPIO、CONFIG_SPI_BITBANG。CE 接 24 脚 PE0，SCLK 接 23 脚 PE1，I/O 接 19 脚 PE2，没有外接上拉。GPIO 复用由驱动切换，pinmux 不用手写。官方 Ubuntu 的 6.6 内核已带这个修复。

修好位序后我没有先上板，又按「采样撞高阻」的推测改了 SPI 模式和延时。实测这些改动都是多余的，真实延时反而有害，最后退回了 Mode 0。

MAX98357A

模块 40pin SoC
VIN 2 或 4 5V
GND 6
BCLK 12 PB5
LRC 35 PB6
DIN 40 PB7

设备树里关掉了占用 PB7 的 &twi1，从 pinctrl 组里去掉了 MCLK 用的 PB4。声卡名写成 sndi2s0，HAL 按这个名字匹配。

defconfig 加了 CONFIG_SND_SOC_MAX98357A=y。放音时 pinmux-pins 里 37 到 39 脚切到 i2s0_*，停止后是 io_disabled。

SD 脚悬空。查手册后发现它是模拟电平输入，电压决定声道，模块自带的上拉让它落在左右平均区间：

SD 电压 行为
低于 0.16V 关断
0.16 到 0.77V 左右平均
0.77 到 1.4V 右声道
高于 1.4V 左声道

GAIN 有五档：悬空 9dB，接 GND 12dB，接 VIN 6dB，经 100kΩ 接 GND 15dB，经 100kΩ 接 VIN 3dB。芯片没有音量寄存器，音量走软件：

风扇温度

风扇默认 90°C 才转，板子待机 35 到 44°C，所以平时一直不转。board.dts 里有两个相近的节点：

风扇挂在 cpul_threshold，从 cooling-device = <&fan0 ...> 上面那行 trip 查到的。我把它和大核的 cpub_threshold 都改成 60°C 起转、55°C 停转。CPU 降频点是 115°C，不受影响。

SD 卡报错

系统弹「SD 卡出现问题」。系统装在这张 TF 卡上，原厂 fstab 又把这个卡槽配成了外置 SD 卡，vold 扫到一堆挂不上的分区。

按分区内容看，点「修正」会格式化存放开机 logo 和字体的分区，我没有点。公共 fstab 有 15 个产品在用，我放了一份产品专属 fstab，注释掉 4020000.sdmmc 那行。调试时执行过 ctl.restart vold，整个系统跟着重启了。

常驻通知

「已启用序列控制台」搜文案搜不到。我用 dumpsys notification 拿到 id 55，反查到 NOTE_SERIAL_CONSOLE_ENABLED，再找到 ActivityManagerService 里的 showConsoleNotificationIfActive()。串口还要用，所以只注释了这个调用。

「正在通过 USB 为连接的设备充电」来自 UsbDeviceManager，这条没有改。

USB adb

供电口同时是 USB2.0 口，adb 走这个口，另一个 Type-C 手册写只支持 Host。这个口开机后停在 Host，电脑认不到，没接屏幕时也进不了开发者选项。

查下来有两层原因。内核的自动检测因为设备树配置组合不受支持，没有启动，这个口也没有 ID 脚。随后 SystemUI 读取开发者选项，默认关，把口写成了 Host。

临时切换走串口，重启后失效：

2 是 Device，1 是 Host。sysfs 里叫 10.usbc0，设备树里叫 usbc0@10。/sys/class/usb_role/ 和 typec/port0/data_role 都试过，切不了这个口。

测试镜像里，我把 SettingsProvider 的 def_otg_mode_switch 改成 true，并给 CentralSurfacesImpl.setOtgMode() 补了开机时节点为 null 的分支。

adb 安全

userdebug 构建下 ro.adb.secure=0，厂商默认开了 5555 端口，su 不做授权，bootloader 也是解锁的。实测同一局域网可以无凭据拿到 root。

我删掉了 device-common.mk 里的 service.adb.tcp.port=5555，保留 USB adb。ro.adb.secure 没有改，位置在 device/softwinner/jupiter/common/system/config.mk。

调试记录

串口

参数 115200-8-N-1，无流控。

  • Windows 串口是独占的。有一次打开成功但读到 0 字符，是另一个终端占着。
  • 板子上的 su 不支持 -c，写法是 su 0 <命令>。
  • 串口里已经在板子上，没有 adb 命令。
  • 控制台约 80 列折行，内核日志也会插进命令输出。

板子掉线时，开机日志里有 FAT-fs (mmcblk0p1): Volume was not properly unmounted，判断为硬断电，软重启不会留这条。

sshd

系统不带 sshd，我用了静态编译的 dropbear，过程中改了这几处：

  • /etc/passwd 是空的，写了一份再 mount -o bind 盖上去。
  • shell 写 /system/bin/sh 被拒，改成 /bin/sh。
  • -D 对目录权限要求太严，去掉了。
  • hostkey 换成绝对路径，守护化后工作目录会变成 /。
  • adb 里直接起的后台进程随会话退出，改成脚本启动。

-s 禁用了密码登录。scp 和 sftp 用不了，传文件走 ssh ... 'cat > 路径'。

Windows

PhoenixCard 双击没反应，当时它在中文目录里，挪到纯英文路径后正常。它只允许一个实例，已有实例时再启动也会静默退出。

PowerShell 5.1 的 Get-Content 和 Set-Content 默认走 ANSI，一次把踩坑文档损坏了约 1000 个汉字，后来从会话记录重放编辑恢复。重放时 JS 的 replace 把内容里的 $' 当成了特殊替换，改成函数式写法才对。

其他记录：

  • .bat 和 .vbs 带中文时解析失败，改成只写 ASCII。.bat 的 echo 里的圆括号也转义了。
  • sh 脚本带 CRLF 时报语法错误，改成 LF。中文经 ssh 管道后编码错乱，改用 adb push。
  • Start-Process -RedirectStandardError 遇到同时存在的 NO_PROXY 和 no_proxy 报错，改用 .cmd 重定向。
  • adb exec-out screencap -p > a.png 在 PowerShell 里损坏图片，改成存到板子上再 adb pull。
  • Git Bash 改写 /home/... 参数，加了 MSYS_NO_PATHCONV=1。
  • 用 shell 转义判断换行风格出过错，后来改成数字节。

网络

排查 DNS 时 114.114.114.114 不通，阿里、腾讯、百度的 DNS 都通。查询不存在的域名返回 unknown host，判断没有劫持。Android 的 resolv.conf 是空的，DNS 从 dumpsys connectivity | grep -i DnsAddresses 看。

待验证
