摸下泰山pi诶
2026-08-11 22:34:28 #linux

背景

最近耳朵听模型部署都起茧子了，寻思把泰山派掏出来清清灰

编译buildroot

个人理解是开发半场上自带的基本芯片映射驱动，点灯只需要一条指令

这部分参考 SDK编译

配网

这块泰山派当前这套系统里：

  • Wi-Fi 模组是 AP6212A / BCM43438A1
  • 只支持 2.4G
  • 不能连 5G
  • 真正要改的配置文件是：
/userdata/cfg/wpa_supplicant.conf

不是只改 /etc/wpa_supplicant.conf。

而且这套系统里 ifupdown 对 wpa-conf 支持不靠谱，最稳的方法是自己写启动脚本：

上电驱动
→ wpa_supplicant 负责连 Wi-Fi
→ udhcpc 负责拿 IP

驱动

作用：

让系统识别 Wi-Fi 芯片，生成 wlan0

你看到的这类日志：

bcmdhd.ko
fw_bcm43438a1.bin
nvram_ap6212a.txt

就是驱动、固件、NVRAM 被加载。

检查命令：

iw list
ip link show wlan0

你这次 iw list 只有：

Band 1: 2412~2472 MHz

所以确定：

只支持 2.4G

扫描 Wi-Fi

作用：

看看周围有哪些 AP

命令：

iw dev wlan0 scan | grep -E "SSID:|freq:|signal:"

你后来已经扫到了：

SSID: Tomorrow is another day 2.4G
signal: -50 dBm

说明：

  • 路由器 2.4G 正常
  • 板子能看到它
  • 不是信号问题

连接

作用：

拿着 SSID 和密码，真正连上 AP

核心程序：

wpa_supplicant

它读的配置文件是：

/userdata/cfg/wpa_supplicant.conf

典型内容：

ctrl_interface=/var/run/wpa_supplicant
ap_scan=1
update_config=1

network={
    ssid="Tomorrow is another day 2.4G"
    psk="7678321.Com"
    key_mgmt=WPA-PSK
}

成功标志：

iw dev wlan0 link

输出类似：

Connected to xx:xx:xx:xx:xx:xx
SSID: Tomorrow is another day 2.4G

失败时常见现象：

  • Not connected.
  • WPA failed
  • 一直扫描

拿 IP

作用：

连上 Wi-Fi 后，向路由器申请 IP 地址

核心程序：

udhcpc

命令：

udhcpc -i wlan0

成功后查看：

ip -4 addr show wlan0
ip route

正常应该得到：

192.168.31.x/24
default via 192.168.31.1

如果你看到：

169.254.x.x

说明：

Wi-Fi 没连上，或者 DHCP 没成功

这是“自救地址”，不是正常联网地址。

三个核心

1. wlan0

它是：

无线网卡接口

2. wpa_supplicant

它负责：

连接 Wi-Fi

不是拿 IP。

3. udhcpc

它负责：

拿 IP 地址

不是连接 Wi-Fi。

所以整条链路是：

wlan0 出现
→ wpa_supplicant 连 Wi-Fi
→ udhcpc 拿 IP

改错配置文件

你最初改的是：

/etc/wpa_supplicant.conf

但系统实际用的是：

/userdata/cfg/wpa_supplicant.conf

把 DHCP 问题当成 Wi-Fi 问题

其实顺序不能反。

必须先确认：

iw dev wlan0 link

如果这里还是：

Not connected.

那就别看 DHCP。

因为：

没连上 Wi-Fi
→ udhcpc 一定拿不到 IP

配网步骤

1. 写好配置文件

vi /userdata/cfg/wpa_supplicant.conf

内容：

ctrl_interface=/var/run/wpa_supplicant
ap_scan=1
update_config=1

network={
    ssid="Tomorrow is another day 2.4G"
    psk="7678321.Com"
    key_mgmt=WPA-PSK
}

2. 清理旧进程

killall udhcpc 2>/dev/null
killall dhcpcd 2>/dev/null
killall wpa_supplicant 2>/dev/null

3. 启用接口

ip link set wlan0 up
mkdir -p /var/run/wpa_supplicant

4. 连接 Wi-Fi

wpa_supplicant -B \
  -i wlan0 \
  -c /userdata/cfg/wpa_supplicant.conf \
  -C /var/run/wpa_supplicant \
  -f /tmp/wpa.log

5. 看有没有连上

iw dev wlan0 link

如果输出：

Connected to ...
SSID: Tomorrow is another day 2.4G

说明认证成功。

6. 拿 IP

udhcpc -i wlan0

7. 查看结果

ip -4 addr show wlan0
ip route

开机自动联网方案

因为系统自带的 S40network + S41dhcpcd 不稳定，建议自己写一个脚本。

例如：

vi /etc/init.d/S42wifi

内容：

#!/bin/sh

case "$1" in
    start)
        killall udhcpc 2>/dev/null
        killall dhcpcd 2>/dev/null
        killall wpa_supplicant 2>/dev/null

        ip link set wlan0 up
        mkdir -p /var/run/wpa_supplicant

        wpa_supplicant -B \
          -i wlan0 \
          -c /userdata/cfg/wpa_supplicant.conf \
          -C /var/run/wpa_supplicant \
          -f /tmp/wpa.log

        sleep 8
        udhcpc -i wlan0
        ;;
    stop)
        killall udhcpc 2>/dev/null
        killall dhcpcd 2>/dev/null
        killall wpa_supplicant 2>/dev/null
        ip link set wlan0 down
        ;;
    restart)
        "$0" stop
        sleep 1
        "$0" start
        ;;
esac

exit 0

加权限：

chmod +x /etc/init.d/S42wifi

测试：

/etc/init.d/S42wifi restart

七、检查流程

以后遇到 Wi-Fi 不通，就按这个顺序判断：

1. 检查驱动

iw list
ip link show wlan0

没有 wlan0，先看驱动。

2. 是否能扫到 AP

iw dev wlan0 scan | grep -E "SSID:|freq:|signal:"

扫不到 AP，先看路由器、距离、频段。

3. 检查连接状态

iw dev wlan0 link

如果是：

Not connected.

先看 wpa_supplicant 和密码。

4. 是否申请到IP

ip -4 addr show wlan0

如果是：

169.254.x.x

说明 DHCP 没成，或者前面根本没连上。

八、流程图

路由器(2.4G)
    ↓
Wi-Fi 芯片/AP6212A
    ↓
驱动 bcmdhd.ko
    ↓
wlan0
    ↓
wpa_supplicant 负责认证
    ↓
udhcpc 负责拿 IP
    ↓
ip / route / ping / ssh

九、总结

原理

先有网卡
再连 Wi-Fi
最后拿 IP

程序分工

udhcpc         = 拿 IP
iw             = 看无线状态
ip             = 看 IP 和路由

核心文件

/userdata/cfg/wpa_supplicant.conf

核心命令

ip link set wlan0 up
wpa_supplicant -B -i wlan0 -c /userdata/cfg/wpa_supplicant.conf -C /var/run/wpa_supplicant

环境

开机

有一个强制改密码的过程，先登录你设置的默认的用户名密码，然后更改密码就可以了

遇到了两个问题

  1. 开机后打印乱七八糟的东西说是麦克风的i2c数据传输问题，检查后发现是I2S1 RX 时钟配置错误

原 DTS 使用旧属性：

rockchip,clk-trcm = <1>;

Linux 6.1 驱动不会解析该旧属性，已经替换为：

rockchip,trcm-sync-tx-only;

  1. wanl0拉不起来，bcmdhd 的自动固件选型

AP6212 模组内部使用 BCM43430，不同硬件批次存在 silicon revision：

BCM43430 chiprev 0 -> fw_bcm43438a0.bin + nvram_ap6212.txt
BCM43430 chiprev 1 -> fw_bcm43438a1.bin + nvram_ap6212a.txt

DTS 中的：

wifi_chip_type = "ap6212"

只表示模组系列。驱动启动后还会通过 SDIO 读取真实 chiprev，再选择 A0 或 A1。

当前板子日志明确选择：

fw_bcm43438a1.bin

所以它是 revision 1，应配套：

fw_bcm43438a1.bin
nvram_ap6212a.txt

Wi-Fi

  1. A0/A1 是 BCM43430 的不同 silicon revision：

    chiprev 0 -> fw_bcm43438a0.bin + nvram_ap6212.txt
chiprev 1 -> fw_bcm43438a1.bin + nvram_ap6212a.txt

  2. 当前板子是 revision 1。直接复制改名可以临时修复：

    sudo cp /vendor/etc/firmware/fw_bcmdhd.bin \
  /vendor/etc/firmware/fw_bcm43438a1.bin
sudo cp /vendor/etc/firmware/nvram.txt \
  /vendor/etc/firmware/nvram_ap6212a.txt
sudo reboot

  3. 常用正式方案是同时安装 A0/A1 文件，让 bcmdhd 自动选型。新镜像已包含：

    fw_bcm43438a0.bin
fw_bcm43438a1.bin
fw_bcmdhd.bin
nvram_ap6212.txt
nvram_ap6212a.txt
nvram.txt

配网

ubuntu系统与buildroot系统不同不用写脚本执行命令自动配网，而是是用networkmanager

本来要以为需要写个脚本，发现没vim，而且可以一键连接wifi，socool

常用命令

查看：

systemctl is-active NetworkManager
ip route
nmcli device status
nmcli connection show

扫描 Wi-Fi：

nmcli device wifi list

连接：

sudo nmcli device wifi connect "SSID" password "密码"

设置静态 IP：

sudo nmcli con mod "连接名" \
ipv4.method manual \
ipv4.addresses 192.168.31.100/24 \
ipv4.gateway 192.168.31.1 \
ipv4.dns "223.5.5.5 8.8.8.8"

开机自启：

sudo nmcli con mod "连接名" connection.autoconnect yes

查看具体配置：

nmcli con show "连接名"

立即让配置生效：

执行：

sudo nmcli connection down "ssid"
sudo nmcli connection up "ssid"

注意：

如果你现在是通过 SSH 操作板子，执行 down 后 SSH 会立刻断开。

串口操作就没关系。

也可以直接：

sudo nmcli connection up "Tomorrow is another day 2.4G"

检查：

ip -4 addr show wlan0

应该看到：

inet 192.168.31.100/24

然后：

ip routebash

应该有：

default via 192.168.31.1 dev wlan0

测试：

ping -c 3 192.168.31.1

再：

ping -c 3 8.8.8.8

最后验证 DNS：

ping -c 3 www.baidu.com

这样分别验证：

路由器通信
→ 外网通信
→ DNS解析

总结

精简 Buildroot
自己控制：
wpa_supplicant → udhcpc → 启动脚本

Ubuntu

Wi-Fi认证 → IP配置 → DNS → 开机自启

所以在泰山派 Ubuntu 上，“配置静态 IP + 开机自动联网”本身就是配置 NetworkManager，不需要额外脚本。

泰山派 RK3566 编译 Ubuntu 22.04 Desktop 指南

本文记录泰山派 V10（RK3566）从 SDK、Linux 内核到 Ubuntu 22.04 Desktop 镜像的完整流程，并包含 AP6212 Wi-Fi 驱动配置、镜像打包和烧录方法。

1. 最终目标

项目 本次使用的配置
开发板 泰山派 V10
SoC Rockchip RK3566
系统 Ubuntu 22.04.5 LTS Desktop，arm64
内核 Linux 6.1.75
Wi-Fi AP6212A1，SDIO，bcmdhd
构建目录 /home/haxio/tspi
最终镜像 rockdev/update.img

2. 需要准备的内容

宿主机

建议使用 Ubuntu 18.04/20.04 虚拟机，并准备至少 80 GB 可用空间（Desktop rootfs 和镜像会占用较多空间）。安装常用工具：

sudo apt update
sudo apt install -y git make gcc g++ bc bison flex libssl-dev \
  libncurses5-dev device-tree-compiler lz4 liblz4-tool \
  qemu-user-static binfmt-support e2fsprogs rsync unzip wget xz-utils \
  cpio fakeroot

SDK 自带 ARM64 交叉编译器，不要用宿主机的 x86_64 gcc 编译内核。

SDK 和 Ubuntu rootfs

将完整 SDK 解压到：

/home/haxio/tspi

准备官方 Ubuntu Base：

ubuntu-base-22.04.5-base-arm64.tar.gz

它只提供最小 ARM64 用户空间，桌面、网络和 SSH 需要后续安装。

3. 选择泰山派板级配置

cd ~/tspi
./build.sh BoardConfig-rk3566-tspi-v10.mk

确认配置文件中的关键项：

RK_UBOOT_DEFCONFIG=rk3566
RK_KERNEL_DTS=tspi-rk3566-user-v10-linux
RK_CFG_BUILDROOT=rockchip_rk3566

parameter-buildroot-fit.txt 中显示 MACHINE_MODEL: RK3568 是 SDK 对 RK356x 系列共用的元数据，不代表本板是 RK3568；泰山派实际使用 RK3566 U-Boot 和 RK3566 DTS。

4. 编译 U-Boot、内核和模块

cd ~/tspi
./build.sh uboot

export CROSS_COMPILE="$PWD/prebuilts/gcc/linux-x86/aarch64/gcc-linaro-6.3.1-2017.05-x86_64_aarch64-linux-gnu/bin/aarch64-linux-gnu-"
export ARCH=arm64

./build.sh kernel
./build.sh modules

正常产物包括：

kernel/arch/arm64/boot/Image
kernel/arch/arm64/boot/dts/rockchip/tspi-rk3566-user-v10-linux.dtb
kernel/boot.img
rockdev/boot.img
rockdev/uboot.img

如果出现 gcc: unrecognized command line option '-mlittle-endian'，说明 CROSS_COMPILE 没有生效。重新执行上面的 export，并检查：

"${CROSS_COMPILE}gcc" -dumpmachine

结果应为 aarch64-linux-gnu，不能是 x86_64-linux-gnu。

如果旧版 lz4c 报 --favor-decSpeed 或 -12 参数错误，在 kernel/scripts/Makefile.lib 中将：

$(LZ4) -12 --favor-decSpeed stdin stdout

改为：

$(LZ4) -9 stdin stdout

5. 创建 Ubuntu 22.04 Desktop rootfs

cd ~/tspi
mkdir -p ubuntu-rootfs
sudo tar -xpf ubuntu-base-22.04.5-base-arm64.tar.gz -C ubuntu-rootfs
sudo cp /usr/bin/qemu-aarch64-static ubuntu-rootfs/usr/bin/

配置 ARM64 APT 源（Ubuntu Base 默认使用 ports 源）：

sudo tee ubuntu-rootfs/etc/apt/sources.list >/dev/null <<'EOF'
deb http://ports.ubuntu.com/ubuntu-ports jammy main restricted universe multiverse
deb http://ports.ubuntu.com/ubuntu-ports jammy-updates main restricted universe multiverse
deb http://ports.ubuntu.com/ubuntu-ports jammy-security main restricted universe multiverse
EOF

挂载 chroot 所需的虚拟文件系统：

sudo mount --bind /dev ubuntu-rootfs/dev
sudo mount -t proc /proc ubuntu-rootfs/proc
sudo mount -t sysfs /sys ubuntu-rootfs/sys
sudo mount -t devpts /dev/pts ubuntu-rootfs/dev/pts

进入 rootfs 安装桌面和网络组件：

sudo chroot ubuntu-rootfs /bin/bash
export HOME=/root
export LC_ALL=C
apt update
apt upgrade -y
apt install -y ubuntu-desktop-minimal network-manager openssh-server sudo \
  locales language-pack-zh-hans wpasupplicant rfkill wireless-regdb iw

在 chroot 中设置账户、时区和默认图形目标：

useradd -m -s /bin/bash tspi
echo 'tspi:orangepi2026' | chpasswd
usermod -aG sudo tspi
ln -sf /usr/share/zoneinfo/Asia/Shanghai /etc/localtime
echo Asia/Shanghai > /etc/timezone
locale-gen en_US.UTF-8 zh_CN.UTF-8
systemctl enable NetworkManager
systemctl enable ssh
systemctl enable gdm3
systemctl set-default graphical.target
exit

卸载虚拟文件系统：

sudo umount ubuntu-rootfs/dev/pts
sudo umount ubuntu-rootfs/dev
sudo umount ubuntu-rootfs/proc
sudo umount ubuntu-rootfs/sys

配置主机名和 Netplan：

echo tspi | sudo tee ubuntu-rootfs/etc/hostname >/dev/null
sudo mkdir -p ubuntu-rootfs/etc/netplan
sudo tee ubuntu-rootfs/etc/netplan/01-network-manager-all.yaml >/dev/null <<'EOF'
network:
  version: 2
  renderer: NetworkManager
EOF
sudo chmod 600 ubuntu-rootfs/etc/netplan/01-network-manager-all.yaml

6. 将内核模块安装到 rootfs

回到 SDK 根目录，并确认交叉编译器仍然有效：

cd ~/tspi
export ARCH=arm64
export CROSS_COMPILE="$PWD/prebuilts/gcc/linux-x86/aarch64/gcc-linaro-6.3.1-2017.05-x86_64_aarch64-linux-gnu/bin/aarch64-linux-gnu-"

sudo make -C kernel ARCH="$ARCH" CROSS_COMPILE="$CROSS_COMPILE" \
  INSTALL_MOD_PATH="$PWD/ubuntu-rootfs" modules_install
sudo depmod -b ubuntu-rootfs 6.1.75

确认模块已安装：

find ubuntu-rootfs/lib/modules/6.1.75 -name 'bcmdhd.ko*'
test -f ubuntu-rootfs/lib/modules/6.1.75/modules.dep && echo 'modules OK'

如果后续重新编译了不同版本的内核，应使用下面的命令获取实际版本，并将 depmod 后面的 6.1.75 替换为该结果：

make -s -C kernel ARCH=arm64 kernelrelease

7. 配置 AP6212 Wi-Fi

DTS 已启用无线节点，并指定：

wifi_chip_type = "ap6212"

Wi-Fi 固件来自：

external/rkwifibt/firmware/broadcom/AP6212A1/wifi/

bcmdhd 启用了 FW_PATH_AUTO_SELECT。DTS 中的 ap6212 是模组系列名，驱动还会根据 BCM43430 的 silicon revision 自动选择具体文件：

chiprev 0 -> fw_bcm43438a0.bin + nvram_ap6212.txt
chiprev 1 -> fw_bcm43438a1.bin + nvram_ap6212a.txt

因此不能只放一个改名后的通用文件。正式镜像同时保留通用名和 A0/A1 原始名：

sudo mkdir -p ubuntu-rootfs/vendor/etc/firmware
sudo cp external/rkwifibt/firmware/broadcom/AP6212A1/wifi/fw_bcm43438a1.bin \
  ubuntu-rootfs/vendor/etc/firmware/fw_bcmdhd.bin
sudo cp external/rkwifibt/firmware/broadcom/AP6212A1/wifi/nvram_ap6212a.txt \
  ubuntu-rootfs/vendor/etc/firmware/nvram.txt
sudo cp external/rkwifibt/firmware/broadcom/AP6212A1/wifi/fw_bcm43438a0.bin \
  ubuntu-rootfs/vendor/etc/firmware/fw_bcm43438a0.bin
sudo cp external/rkwifibt/firmware/broadcom/AP6212A1/wifi/fw_bcm43438a1.bin \
  ubuntu-rootfs/vendor/etc/firmware/fw_bcm43438a1.bin
sudo cp external/rkwifibt/firmware/broadcom/AP6212A1/wifi/nvram_ap6212.txt \
  ubuntu-rootfs/vendor/etc/firmware/nvram_ap6212.txt
sudo cp external/rkwifibt/firmware/broadcom/AP6212A1/wifi/nvram_ap6212a.txt \
  ubuntu-rootfs/vendor/etc/firmware/nvram_ap6212a.txt
sudo cp external/rkwifibt/firmware/broadcom/AP6212A1/bt/BCM43430A1.hcd \
  ubuntu-rootfs/vendor/etc/firmware/BCM43430A1.hcd

配置模块参数和开机自动加载：

sudo mkdir -p ubuntu-rootfs/etc/modprobe.d ubuntu-rootfs/etc/modules-load.d
sudo tee ubuntu-rootfs/etc/modprobe.d/bcmdhd.conf >/dev/null <<'EOF'
options bcmdhd firmware_path=/vendor/etc/firmware/fw_bcmdhd.bin nvram_path=/vendor/etc/firmware/nvram.txt config_path=/vendor/etc/firmware/config.txt
EOF
echo bcmdhd | sudo tee ubuntu-rootfs/etc/modules-load.d/bcmdhd.conf >/dev/null

驱动参数可离线验证：

modprobe -d ubuntu-rootfs -S 6.1.75 --show-depends bcmdhd

启动后使用 nmcli 或 Ubuntu 桌面网络菜单连接 Wi-Fi。

如果日志出现：

failed /vendor/etc/firmware/fw_bcm43438a1.bin

说明驱动已经完成自动选型，但镜像缺少 A1 原始文件名。不要只修改 DTS；补齐上面的 A0/A1 文件后重新制作 rootfs 和 update.img。

8. 音频 I2S/RK809 配置

播放测试正常但录音出现：

rockchip-i2s-tdm ... rate(0)
ASoC: error at snd_soc_dai_hw_params ... -22

原因是旧 DTS 属性 rockchip,clk-trcm = <1>; 不再被 Linux 6.1 的 I2S-TDM 驱动解析。将 &i2s1_8ch 节点改为：

&i2s1_8ch {
    status = "okay";
    rockchip,trcm-sync-tx-only;
    pinctrl-names = "default";
    pinctrl-0 = <&i2s1m0_sclktx
                 &i2s1m0_lrcktx
                 &i2s1m0_sdi0
                 &i2s1m0_sdo0>;
};

重新执行 ./build.sh kernel 后再打包。验证播放和录音：

speaker-test -D hw:1,0 -c 2 -r 48000 -F S16_LE
arecord -D hw:1,0 -c 2 -r 48000 -f S16_LE -d 5 /tmp/test.wav

9. 制作 rootfs.ext4

制作前删除 chroot 临时文件，避免把宿主环境带入镜像：

sudo rm -f ubuntu-rootfs/usr/bin/qemu-aarch64-static
sudo rm -f ubuntu-rootfs/usr/sbin/policy-rc.d
sudo rm -f ubuntu-rootfs/var/lib/dbus/machine-id
sudo sh -c ': > ubuntu-rootfs/etc/machine-id'
sudo rm -rf ubuntu-rootfs/var/cache/apt/archives/*.deb

当前参数表为 6 GiB rootfs 分区，本次使用 3800 MiB 文件系统：

sudo mkfs.ext4 -F -L rootfs -d ubuntu-rootfs rockdev/rootfs.ext4 3800M
sudo chown "$USER:$USER" rockdev/rootfs.ext4
e2fsck -fn rockdev/rootfs.ext4
ln -sfn rootfs.ext4 rockdev/rootfs.img

10. 生成完整升级镜像

Ubuntu 不使用 Buildroot recovery 时，编辑：

tools/linux/Linux_Pack_Firmware/rockdev/package-file

将下面一行注释掉：

#recovery Image/recovery.img

然后执行：

cd ~/tspi
./build.sh firmware
./build.sh updateimg

成功标志：

Make firmware OK!
New image generated successfully!
Running build_updateimg succeeded.

检查镜像：

ls -lh rockdev/update.img
sha256sum rockdev/update.img

当前已验证的最终镜像 SHA256：

f81dd518d6442f7ebe19cd987b5dc28284a7221166263ebc7872d1636c592a24

11. 使用 RKDevTool 烧录

update.img 是完整 Rockchip 升级包，不需要手动填写各分区地址。

  1. 将 rockdev/update.img 复制到 Windows。
  2. 泰山派进入 Loader 或 Maskrom 模式并连接 USB OTG。
  3. RKDevTool 底部显示“发现一个 LOADER 设备”。
  4. 进入“升级固件”页，点击“固件”，选择 update.img。
  5. 等待固件信息解析完成，点击“升级”。
  6. 等待成功提示，不要断电或拔 USB。

不要把 update.img 填到“下载镜像”页的某个地址；手工地址烧录适用于拆分的 MiniLoaderAll.bin、uboot.img、boot.img、rootfs.img 等文件。

12. 首次启动检查

当前最终镜像账户：

用户名：tspi
密码：orangepi2026

该账户已加入 sudo，且没有设置首次强制改密。tspi2026 不建议作为密码，因为它包含用户名 tspi，会被 Ubuntu 密码质量策略拒绝；orangepi2026 不包含用户名。

系统启动后执行：

sudo resize2fs /dev/disk/by-partlabel/rootfs
df -h /
uname -a
lsmod | grep bcmdhd
iw dev
nmcli device
dmesg | grep -iE 'bcmdhd|firmware|wlan|sdio'

连接 Wi-Fi：

nmcli device wifi list
sudo nmcli device wifi connect "WiFi名称" password "WiFi密码"

13. 常见问题速查

  • gcc ... -mlittle-endian：交叉编译器未生效，重新 export CROSS_COMPILE。
  • recovery.img open file failed：打包清单包含不存在的 Buildroot recovery，注释 recovery 条目。
  • rootfs.img open file failed：没有生成 rockdev/rootfs.ext4，先制作 ext4 镜像。
  • RKDevTool 显示 RK3568：RK356x SDK 共用元数据，确认 U-Boot 为 rk3566、DTS 为 tspi-rk3566-user-v10-linux 即可。
  • 无 Wi-Fi：先看 dmesg 是否有 SDIO、固件路径和 GPIO 电源域错误，再确认 bcmdhd.ko、fw_bcmdhd.bin 和 nvram.txt 均存在。
  • failed ... fw_bcm43438a1.bin：驱动自动选中了 A1，但镜像只放了通用文件名；补齐 fw_bcm43438a1.bin 和 nvram_ap6212a.txt。
  • Authentication token manipulation error：旧镜像的 haxio 账户被设置为首次强制改密，且输入了错误的旧密码或根分区不可写；当前最终镜像已改为 tspi/orangepi2026 并取消强制改密。
  • 音频播放正常、录音失败并出现 rate(0)：检查 I2S1 是否使用 rockchip,trcm-sync-tx-only;，不要继续使用旧的 rockchip,clk-trcm = <1>;。
  • Ubuntu rootfs 空间不足：执行 resize2fs /dev/disk/by-partlabel/rootfs 扩展到参数表的 6 GiB 分区。
