问题小结

24/9/15

问题

  1. 格式化后磁盘只显示15.8M，还以为坏了，实际上是未分配

  2. 无法直接运行 NES 游戏文件 (.nes)：因为 .nes 是游戏 ROM 文件，需要通过 NES 模拟器来运行。

  3. 系统缺少包管理器和常见工具 (apt-get, git, sudo)：Buildroot 系统是精简的嵌入式系统，缺少包管理工具和其他常见的工具，无法通过传统方式安装软件。

解决方案

  1. 都删掉，重新建卷
  2. 确认 Buildroot 系统特性：Buildroot 没有包管理工具，需要手动下载并传输软件或源码到系统。
  3. 下载 NES 模拟器源码：
    • 在主机上（有网络连接的电脑），下载 NES 模拟器 fceux 的源码（从 GitHub 或其他网站下载）。
  4. 通过串口上传文件：
    • 使用串口工具（如 minicom）配合 rz 命令，将下载的源码或预编译的二进制文件通过串口传输到 Buildroot 系统。
  5. 编译或运行 NES 模拟器：
    • 在 Buildroot 系统上编译 fceux（如有编译工具），或者在主机上交叉编译后传输已编译的可执行文件到 Buildroot。
  6. 运行 NES 游戏：
    • 使用 fceux 模拟器运行 .nes 游戏文件。

原理

各部分作用：

组件 作用
ttyS0 物理串口控制台
tty0 当前虚拟终端
fbcon 把终端字符画成像素
/dev/fb0 240×320的RGB565图像缓冲区
fb_st7789v 把帧缓冲像素通过SPI发送到屏幕
console=tty0 让内核日志进入屏幕终端
console=ttyS0 同时保留串口日志

启用后的启动过程：

  1. U-Boot 阶段：仍然只从串口输出；
  2. Linux 启动早期：LCD 驱动还没加载，屏幕暂时没有日志；
  3. 约 2.6 秒时，fb_st7789v 创建 /dev/fb0；
  4. fbcon 自动接管 tty0；
  5. 后续内核启动日志自动显示到 LCD。

遇到的问题汇总

问题 原因 解决方法
插入网卡只有 /dev/sda AIC8800DC 默认先进入虚拟驱动盘模式 a69c:572a eject /dev/sda，切换为 368b:88e5
切换后没有 wlan0 内核没有 AIC8800DC 驱动 交叉编译 aic_load_fw.ko、aic8800_fdrv.ko
驱动编译前缺少符号 内核未启用 CFG80211 启用 CONFIG_CFG80211=y、CONFIG_RFKILL=y 并重编内核
驱动能编译但镜像没有 外部模块不会自动进入 Buildroot 把 .ko 复制到 rootfs overlay 的 /lib/modules/.../extra/
驱动找不到固件 AIC 固件未进入根文件系统 复制 fw/aic8800DC 到 /lib/firmware/aic8800DC/
regulatory.db failed 镜像未包含无线国家法规数据库 不影响当前2.4GHz联网；以后启用 BR2_PACKAGE_WIRELESS_REGDB=y
大量 patch_tbl LOGERROR 驱动错误地用错误级别打印补丁表内容 没有 bin upload fail 且出现 wlan0，可以忽略
169.254.x.x 地址 没有从路由器取得 DHCP 地址 先确认 Wi-Fi 认证完成，再运行 DHCP
连接到了 midea_db_4408 原来的配置仍指向开放热点 重新生成 /etc/wpa_supplicant.conf
写配置提示权限不足 sudo 没有作用于 shell 的 > 重定向 使用 sudo tee 或用 root shell 写文件
Invalid passphrase character 变量中有错误或不可见字符，且旧变量未重新输入 清理 \r\n，或者直接用明确参数生成配置
wpa_cli 找不到控制接口 启动 wpa_supplicant 时没有控制目录 添加 -C /var/run/wpa_supplicant
一直连接但不成功 日志明确显示 WRONG_KEY 使用正确密码重新生成 PSK
Babble、VBUS_ERROR USB总线异常，可能是供电波动、连接质量或切换时异常 重新 eject；检查5V供电、线材，必要时使用供电Hub
USB恢复后仍无 wlan0 USB重新枚举后启动脚本已经退出，模块也未加载 手动重新 insmod 两个模块；后续改成自动重试
debugfs already exists 反复认证后驱动残留调试节点 当前连接成功，不影响使用；USB/模块重载可清理
重复运行 DHCP，IP从 .144 变成 .145 再次请求租约，路由器可能分配新地址 正常启动只运行一个 DHCP 客户端，不要反复执行
